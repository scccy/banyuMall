## 问题分析

### 错误1：服务发现问题
- **错误信息**: `Load balancer does not contain an instance for the service service-auth`
- **错误类型**: 微服务间通信问题
- **根本原因**: 
  1. service-auth服务虽然正在运行，但可能未正确注册到Nacos
  2. 两个服务使用了不同的namespace：service-auth使用`ba1493dc-20fa-413b-84e1-d929c9a4aeac`，企业微信服务使用`4fb1aca6-1629-44bb-bf94-5ce5f2cae120`
- **影响范围**: 企业微信服务无法获取配置信息

### 错误2：JSON反序列化问题
- **错误信息**: `Cannot deserialize value of type java.time.LocalDateTime from String "2025-08-06 16:54:22"`
- **错误类型**: 日期格式解析问题
- **根本原因**: 
  1. 项目使用FastJSON2作为JSON序列化工具，但Feign客户端仍在使用Jackson
  2. Jackson默认的LocalDateTime格式是ISO格式（如：2025-08-06T16:54:22），但数据库返回的是"2025-08-06 16:54:22"格式
  3. 缺少Jackson的日期格式配置
- **影响范围**: 配置信息无法正确解析

## 解决方案

### 解决方案1：统一Nacos命名空间
**问题**: 两个服务使用不同的namespace导致服务发现失败
**解决**: 将企业微信服务的namespace修改为与service-auth一致
```yaml
spring:
  cloud:
    nacos:
      discovery:
        namespace: ba1493dc-20fa-413b-84e1-d929c9a4aeac  # 与service-auth保持一致
      config:
        namespace: ba1493dc-20fa-413b-84e1-d929c9a4aeac  # 与service-auth保持一致
```

### 解决方案2：配置Jackson日期格式
**问题**: Jackson无法解析"2025-08-06 16:54:22"格式的LocalDateTime
**解决**: 在企业微信服务中添加Jackson配置
```yaml
spring:
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8
    deserialization:
      fail-on-unknown-properties: false
```

### 解决方案3：使用FastJSON2替代Jackson（推荐）
**问题**: 项目使用FastJSON2但Feign仍用Jackson
**解决**: 配置Feign使用FastJSON2
```java
@Configuration
public class FeignConfig {
    @Bean
    public Decoder feignDecoder() {
        return new FastJsonDecoder();
    }
}
```
