#### 数据来源和字段映射

**排行榜查询SQL**：
```sql
SELECT 
    ptd.user_id,
    ptd.total_reward,
    ROW_NUMBER() OVER (ORDER BY ptd.total_reward DESC) as rank
FROM (
    SELECT 
        user_id, 
        SUM(reward_amount) as total_reward
    FROM publisher_task_detail 
    WHERE completion_time BETWEEN ? AND ?
    GROUP BY user_id
) ptd
ORDER BY ptd.total_reward DESC
LIMIT (从task_config解析出的topCount)
```

**返回字段说明**：
- `rank`: 排行名次（1, 2, 3...）
- `user_id`: 用户ID，来源：`publisher_task_detail.user_id`
- `nickname`: 微信昵称，来源：`sys_user.wechat_nickname`（通过user_id关联）
- `total_reward`: 累计奖励金额，来源：`publisher_task_detail.reward_amount` 汇总

**关联查询**：
- 主表：`publisher_task_detail`
- 关联表：`sys_user`（获取微信昵称）
- 关联条件：`publisher_task_detail.user_id = sys_user.user_id`

**时间范围支持**：
- 自定义时间范围：支持用户选择任意开始和结束时间
- rankQueryType时间范围：支持预设的时间范围类型
  - `1`: 本周（从本周一开始到当前时间）
  - `2`: 本月（从本月1号开始到当前时间）
- 智能默认时间范围：当未指定任何时间范围时，自动选择最合适的时间范围
  - 如果是周一：返回本周一 00:00:00 到当前时间
  - 如果不是周一：返回上周一 00:00:00 到当前时间
- 时间范围优先级：自定义时间范围 > rankQueryType时间范围 > 智能默认时间范围

### 重要发现：任务配置结构
通过分析代码发现，排行榜查询的数量配置存储在：
- **表**: `publisher_task_detail`
- **字段**: `task_config` (JSON格式)
- **配置项**: `topCount` - 控制排行榜前N名
- **示例**: `{"topCount": 50, "inviteeReward": 40}`
